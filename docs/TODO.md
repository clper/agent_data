## P1 — 对回答质量有明确提升

### 1. 多轮上下文消解增强
**状态**：待实施
**问题**：`QueryState` 用正则解析 SQL，子查询/窗口函数失效。"销售部收入→研发部呢→那上个月呢？"无法正确继承上文。
**方案**：
- 基于 SQL 模板化的上下文消解：把上一轮 SQL 结构化为 `SELECT {metrics} FROM {tables} WHERE {filters}`
- 用户说"研发部呢"时，替换 filter 值而非重新生成
- 修改 `state.py.QueryState` 的 SQL 解析逻辑（当前用正则，改为 sqlglot AST 提取）

### 2. SQL 参数化 bug 修复
**状态**：待实施
**问题**：Q25 失败根因——sqlglot 参数化时将 `__PARAM_X###` 插入到 `c.amount` 中间，变成 `c'__PARAM_1###'amount`，SQL 解析失败。
**方案**：修复 `compiler.py` 中参数化逻辑，确保不在标识符中间插入占位符。

### 3. BM25 检索增强（同义词映射）
**状态**：待实施
**问题**：Q07 失败根因——jieba 分词"薪"无法匹配"薪水/薪资"，BM25 要求精确 token 匹配。
**方案**：在检索器中加同义词映射表，检索时自动扩展查询词（如"薪" → "薪水/薪资/调薪"）。

## P2 — 锦上添花

### 4. 查询结果缓存
**状态**：规划中
**描述**：相同问题 5 分钟内重复问，直接返回缓存结果，减少 LLM 调用延迟。
**方案**：`dict` 存 `{question_hash: (answer, timestamp)}`，简单高效。

### 5. Golden Dataset 扩充到 100 题
**状态**：规划中
**描述**：当前 70 题覆盖不够，复合问题（L6）只有 5 题。补充更多跨表复杂查询场景。

### 6. 解释层差异化
**状态**：规划中
**描述**：当前 `_explain()` 对所有查询用同一套 prompt。可按查询类型差异化：趋势类用"上升/下降"描述，排名类用"第1名是..."，比率类用百分比。

### 7. 置信度评估
**状态**：规划中
**问题**：系统对所有问题都给出确定性回答，无"我不确定"能力。
**方案**：检索匹配度低时（BM25 分数低于阈值）或 SQL 生成为空时，主动告知用户不确定性。

### 8. Schema 检索自适应粒度
**状态**：规划中
**问题**：固定 `top_k=6`，简单问题浪费 token，复杂问题表不够。
**方案**：根据问题复杂度（关键词数/是否复合问题）动态调整 top_k（2-10）。

### 9. 角色适配回答
**状态**：规划中
**问题**：`_explain()` prompt 固定，不区分 CEO/经理/员工。
**方案**：`_explain()` 注入用户角色信息，CEO 给全局趋势，经理聚焦本部门。

### 10. Few-shot 示例动态更新
**状态**：规划中
**描述**：验证器重试成功时，自动将修正后的 SQL 加入示例库，持续积累高质量示例。
